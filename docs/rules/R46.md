## 46. Planet exploration upon gaining control — ✅ VERIFIED (tirules2.com) + ⚠ ASSUMPTIONS

📎 tirules: [Exploration](../../../../rules_tirules/R_exploration.md) · [Exploration Cards (notes)](../../../../rules_tirules/C_exploration_cards.md) · [Attach](../../../../rules_tirules/R_attach.md) · [Control](../../../../rules_tirules/R_control.md) · [Relics](../../../../rules_tirules/R_relics.md) · [Frontier Tokens](../../../../rules_tirules/R_frontier_tokens.md)

Code: `core/exploration.py`, `api/routers/exploration.py`, `api/schemas_exploration.py`; UI `frontend/src/domains/exploration/`. Cards (type, text, resolution) exclusively from the component catalog (`ComponentCategory.EXPLORATION`).

### 46.1. Rules

- (X1) A player who gains control of a planet NOT controlled by anyone **explores** it: draws and resolves a card from the deck matching the planet's trait (cultural / hazardous / industrial). A planet without a trait (Mecatol Rex, home planets, space stations) is not explored.
- (X2) Planet with multiple traits → player chooses the deck. Multiple planets at once → player chooses the order; each card is resolved IN FULL before the next. The card is revealed to everyone before resolution.
- (X3) Resolution: the player reads the card, makes decisions, and executes the effect. A card other than a relic fragment or attach goes to its deck's discard pile; a card that purges itself (wormhole tokens) does NOT go to the discard pile. Empty deck → discard pile is shuffled into a new deck.
- (X4) A card with the "attach" header stays attached to the planet (even after control changes — R_attach). A "relic fragment" card lies face up in the player's play area (they can be exchanged in transactions — RULES.md 47).
- (X5) Commodity limit: a player cannot have more than their commodity value (notes on Abandoned Warehouses / Functioning Base / Local Fabricators).

### 46.2. Model and implementation

- `GameState.exploration: ExplorationState | None` (`player_id`, `position`, `queue`, `current`, `log`) — the window opens in `invasion._establish_control` for planets from `result["explore"]` (captured, no previous owner, has trait). A card is drawn **automatically** when there is no choice (one planet in queue, one trait); otherwise the player chooses the planet (order) and deck (`exploration.draw`).
- Decks: `DecksState.exploration_deck/_discard` (key = deck name), seeded LAZILY on first draw (`next_rng` — seedable, Undo-safe). `GameState.planet_attachments {planet: [card]}`, `PlayerState.relic_fragments [card]` (PUBLIC).
- Resolution: `exploration.options_for` (options with `enabled` flag and reason) → `exploration.resolve(option, param)`; closing the window: `exploration.finish` (only when the queue is empty and no card is revealed).
- Locks: `invasion.advance` from ESTABLISH, `tactical.next_step`, and `tactical.end_action` → 422 while exploration is in progress. God-Mode (`end_tactical_action`, `set_step`) clears the window.
- API: `GET /exploration`, `POST /exploration/{draw, resolve, finish}`; `gameState.activeExploration` signal in web-data.
- Automated effects: Freelancers (production, X7), Gamma Wormhole (token, X8), Mercenary Outfit (infantry), Volatile Fuel Source (token to chosen pool), Expedition (ready), Core Mine (TG), Abandoned Warehouses, Functioning Base (action card draw), Local Fabricators (mech), all attach cards (including Demilitarized Zone: structures disappear, ground forces return to orbit), and relic fragments.

### 46.3. ⚠ ASSUMPTIONS / TODO

- (X9) **Exploration before "after you gain control"** (R_exploration notes 1): `set_planet_control` emits
  `PLANET_CONTROL_GAINED/AFTER` at once, but `triggers.accept_offer` refuses such an offer (Integrated Economy…)
  while its planet is still in `ExplorationState.queue` / `current` — the player explores first, then accepts.
- (X6) **Stats from attachments** — `core/planet_stats.py` is the SOLE source of planet resources, influence, and technology specialties after attachments (modifiers from `AttachmentDef` data). Consumers: payment and production budget, dock PRODUCTION value (`planet resources + N`), objectives (progress, payment, "tech skip"), player economy in web-data. Research Facility: the planet gains a specialty; if it already has one → resources and influence +1 INSTEAD. Data can duplicate a specialty (e.g., Tiamat) — only one counts. Code outside `planet_stats` MUST NOT read `registry.planets[..].resources` directly.
- (X7) **Freelancers**: the "produce" option opens `GameState.production_grant` (1 unit in the explored planet's system - "this system" - influence counts as resources — note: the planet pays with resources OR influence, so value = max). This is the production window (the same as in the PRODUCTION step) outside that step: limit comes from the card instead of PRODUCTION value, no docks, blockade of ships in a system with foreign ships still applies, ground forces go onto the player's planets in the system or into space. Does not consume the PRODUCTION step limit. Exploration (next card, "Done") waits for production or skipping (`POST /tactical/production/skip-grant`).
  - Outside the explorer's own tactical action (another player's turn, e.g. Naaz-Rokha agent, or a system other than the active one) the grant is `free`: production runs at the explored system, capacity / fleet pool are checked right after it. Inside it the grant stays tied to the active system.
- (X8) **Gamma Wormhole**: the card places `SystemState.wormhole_tokens += ["GAMMA"]` and is purged. `HexGrid.sync_token_wormholes` connects all systems with such a token (alongside built-in wormholes); the API context synchronizes the map with the state on EVERY `current_grid` read, so Undo/Redo removes the token from the graph as well. Objectives (`View.wormholes`) and the map (`gamma` token in space, web-data) see it like a built-in one.
- ⚠️ SIMPLIFICATION / GAP (`C_exploration_cards.md`): when no mech / infantry is in reinforcements, the option is unavailable (the rule allows removing a unit from the board from a system without your command token — unimplemented).
- ⚠ ASSUMPTION: all captured planets are already controlled at the moment of exploration (rule: multiple planets in a system → "capture and explore one by one"); affects only Freelancers, which is manual anyway.
- ⚠ TODO: frontier exploration (Dark Energy Tap, frontier tokens, Enigmatic Device, Ion Storm), "explore" as a separate card/ability effect, relics (resolving fragments), Dead World / Entropic Field and other non-base PoK cards, trading in the window after revealing a card (transactions — RULES.md 47).

### 46.4. Card piles (deck / discard / purge) and debug tools

- (X9) Each card is in ONE place: in the deck, in its deck's discard pile, in the shared purge pile (`DecksState.purged`), in a player's hand/play area (relic fragments), attached to a planet, or currently revealed. A drawn card leaves the deck; a purged card (wormhole token) does NOT go to the discard pile and does not return on shuffle.
- (X10) The General panel (Card pool) shows deck state from `cardPool`: number of cards REMAINING in the exploration decks (cultural / hazardous / industrial / frontier) and action card deck, discard piles per deck, and a single purge pile. Deck card lists are sent SORTED (they do not leak order). Draw chance = copies of card / cards in deck (computed on the frontend).
- (X11) **Debug** (`core/deck_piles.move_card`, `POST /decks/move`, God-Mode — bypasses rules): moves a card between deck / discard / purge. Target `top` = top of deck, i.e., setting which card will be drawn NEXT; `deck` = random position. "Debug" toggle in the decks window (persisted in localStorage). Top of deck (`cardPool.exploreTop`) is visible only in debug mode.
- ⚠ ASSUMPTION: relic, agenda, and objective decks do not track piles yet (relics have no deck in game state); the action card deck shows the full pool until the game goes through setup.
- (X12) **Exploration hooks (audit 2026-11-11).** After resolving a PLANET exploration card, `exploration.resolve` emits `GameEvent.PLANET_EXPLORED` (AFTER; ctx: `player`, `planet`, `deck`, `card`) — factions/cards "after exploring a planet" attach via `@on_event`. Frontier (`exploration_frontier`) has no planet and does not emit the event. Card effects go through central points (`unit_ops`, `economy`, `command_tokens`, `relic_fragments`), so their hooks (e.g., `UNIT_PLACED`) fire normally.
- ⚠ Known gaps (NOT coded): Naaz-Rokha *Distant Suns* (extra card from the same deck) and *Fabrication* (no MODIFY point for number of cards drawn); DMZ moves ground forces into orbit without its own capacity check (limit caught by `core/limits`, RULES.md 42.x).
- (X13) **Frontier cards with tokens / to hand (source: `C_exploration_cards.md`).**
  - *Enigmatic Device* (ed1/ed2): goes to `PlayerState.frontier_cards` (public), in UI under the **Action cards** tab (draggable like an action card). ACTION (component action): spend 6 resources (planets + TG), purge the card, research 1 technology; without 6 available resources it cannot be played. Code: `core/frontier_cards.py`, `core/hooks/frontier_cards.py`, `/frontier-card/*`.
  - *Ion Storm*: the player chooses the active side (ALPHA/BETA) when placing; the token is a wormhole of that side (`SystemState.ion_storm`, graph via `token_wormholes()`), the card lies in the common play area (`DecksState.common_play_area`). At the end of the movement / retreat step of a tactical action in which ships passed through this wormhole, the token flips to the other side (`core/ion_storm.py`); movement outside these steps (Skilled Retreat) does not flip it. Only one Ion Storm on the board. ⚠ Usage is detected for movement whose destination is the system with the token; multi-step routes through Ion Storm as an intermediate system and choosing "which wormhole" in a system with two wormholes of the same type are not modeled.
  - *Mirage*: planet `mirage` (assets) attached to the system (`added_planets`), the explorer gains it readied, the card is purged, and then EXPLORES it
    (R_exploration: gaining an unowned planet = exploration; Mirage is cultural, exploration queue in the same window).
    ⚠ Legendary ability *Mirage Flight Academy* is not coded (the engine lacks legendary planet ability infrastructure).
