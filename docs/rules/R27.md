## 27. Exhausting components: planets, technologies, leaders (exhaust/ready) — ✅ VERIFIED (LRR + data)

📎 tirules: [Exhausted](../../../../rules_tirules/R_exhausted.md) · [Readied](../../../../rules_tirules/R_readied.md) · [Status Phase](../../../../rules_tirules/R_status_phase.md) · [Planets](../../../../rules_tirules/R_planets.md) · [Technology](../../../../rules_tirules/R_technology.md)

Milestone E4 (component control). **Design decision:** table assistant — the operator manually
toggles state, the app does NOT enforce when a component becomes exhausted. The backend holds
state and commits to history (Undo works).

**Planets and technologies** have a READY / EXHAUSTED state. In TI4, a planet is exhausted
when spending its resources or influence; some technologies (unit/action) also exhaust.
Refreshing (ready) happens in the status phase ("Ready Cards"). Source: LRR 2.0, entries
"Exhausted" and "Status Phase" (TI Wiki / Living Rules). Components without state (e.g.,
passive technologies) can still be marked — this is an operator tool, not a rule validator.

**Model:** `PlayerState.exhausted_planets: list[str]`, `PlayerState.exhausted_technologies:
list[str]` (ready = controlled/owned and NOT in the list). Leaders have a separate, existing
state in `leader_states: {leader_id: "locked"|"unlocked"|"exhausted"}` (RULES.md 18).

**Core:** `board_edit.toggle_planet_exhaust`, `toggle_tech_exhaust` (toggles presence in the
list), `set_leader_state` (sets one leader's state, merges with the rest). **API:**
`POST /player/planet/toggle-exhaust`, `/player/tech/toggle-exhaust`, `/player/leader/set-state`.
**Web-data:** `playerData.exhaustedPlanets`/`exhaustedTechs` (filtered to actually owned) +
`exhausted` flag in `PlanetEntityData` (`tileUnitData[pos].planets[id].exhausted`).

**UI — context menu (right mouse button), NOT component action.** Exhausting is a general
part of gameplay, so it did NOT live in the "Component" tab of the action panel (that one is
for component ACTIONS = cards labeled "ACTION", milestone E4). Instead: RMB on a player's
component in the player panel opens a menu with "Exhaust / Ready" (for leaders also
"Unlock/Lock"). Menu component: `frontend/src/shared/ui/ContextMenu` (`useContextMenu` +
`ContextMenu`) — positioned at cursor, portaled, extensible via an item list (we'll add more
later). Wired into `PlanetCard`, `Tech`, `LeaderChip`, `CompactLeader`; `player_id` (`discordId`)
threaded into ALL three player panel variants: `PlayerCardDeck` (full panel),
`PlayerCardSidebar` (map sidebar), and `PlayerDeckRow` (deck row; techs via `TechGridMobile`) —
through `PlayerCardPlanetsArea`/`Leaders`/`buildTechElementsForType`. Actions call
`useBoardEditor.togglePlanetExhaust/toggleTechExhaust/setLeaderState`.

**System tile context menu (map):** RMB on a tile (`MapTile`) → "Activate system" — calls
`useBoardEditor.activateSystem(position)` (`POST /tactical/activate`), which PLACES a command
token of the ACTIVE player in the system's space, sets `active_system` and step `MOVEMENT`,
and removes 1 from the tactic pool (`core.tactical.activate_system`, RULES.md 19). The item is
disabled when there is no active player (`active_player_id` is None → backend 422). The menu
skips hyperlane/embedded tiles. This is the same action as the "Activate system" button in the
phase panel — the RMB menu bypasses click mode (`activateMode`) and invokes it directly.
