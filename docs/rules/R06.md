## 6. Game Phases — Mapping to Frontend Format — ✅ (format), ⬜ (logic)

📎 tirules: [Game Round](../../../../rules_tirules/R_game_round.md) · [Strategy Phase](../../../../rules_tirules/R_strategy_phase.md) · [Action Phase](../../../../rules_tirules/R_action_phase.md) · [Status Phase](../../../../rules_tirules/R_status_phase.md) · [Agenda Phase](../../../../rules_tirules/R_agenda_phase.md)

Frontend (`GamePhase` in `entities/data/types.ts`) uses lowercase strings with
subphases: `strategy`, `action`, `status.scoring`, `status.homework`, `agenda.*`,
`setup.*`, `finished`. Our `Phase` enum (STRATEGY/ACTION/STATUS/AGENDA) is mapped in
`web_data.py` → `_to_web_phase` (STATUS→`status.scoring`, AGENDA→`agenda.voting`).
`gameState.activePlayer` is the player's COLOR (not id) — the frontend matches by color.

Full phase LOGIC (transitions, actions, timing) = Layer B (roadmap M2–M6), ported from
`TI4_map_generator_bot/src/main/java/ti4/service/{turn,strategycard,tactical,combat,agenda}`.
