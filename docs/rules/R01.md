## 1. Anomalies

📎 tirules: [Anomalies](../../../../rules_tirules/R_anomalies.md) · [Asteroid Field](../../../../rules_tirules/R_asteroid_field.md) · [Nebula](../../../../rules_tirules/R_nebula.md) · [Supernova](../../../../rules_tirules/R_supernova.md) · [Gravity Rift](../../../../rules_tirules/R_gravity_rift.md) · [Movement](../../../../rules_tirules/R_movement.md)

Source: LRR 2.0, "Anomalies" section; TI Wiki /wiki/Anomalies.
Content paraphrased for license compliance.

Key architectural distinction:
- **Adjacency** — a static map property, independent of the player.
  Two systems are adjacent geometrically or via a wormhole. Needed among others for
  Space Cannon, "in an adjacent system" abilities, etc.
- **Traversability** — whether a ship *can* move through or into
  a system. Depends on anomalies, player technologies, and which system is active.
  This is NOT a property of the adjacency graph — it is the movement logic layer.

### 1.1. Asteroid Field — ✅ VERIFIED
- Ships **cannot move through or into** an asteroid field...
- ...**unless** the player owns the **Antimass Deflectors** technology (then movement is allowed).
- Code takeaway: **player-dependent** block (owned technology) — NOT static.
- Flag in AsyncTI4 data: `isAsteroidField`.
- Source: TI Wiki /wiki/Anomalies; TI3-SA /wiki/System.

### 1.2. Nebula — ✅ VERIFIED
- A ship may **enter** a nebula even when it is **not the active system** (also by retreat or by moves
  outside a tactical action), but may **not move through** it — ✅ user decision 2026-11-24 adopting the
  stated design intent (`R_nebula` notes/2–3; the Rules Reference text 1 still says "only if active").
- A ship starting the "Movement" step in a nebula has a **move value = 1**
  for the duration of that step (can be increased by other effects).
- The defender in a nebula gets **+1 to combat**.
- Code takeaway: affects movement (entry condition + move=1 when exiting) and combat
  (defense bonus) — does NOT block static adjacency.
- Flag in data: `isNebula`.
- Source: TI Wiki /wiki/Anomalies.

### 1.3. Supernova — ✅ VERIFIED
- Ships **cannot move through or into** a supernova. Always impassable.
- Code takeaway: **unconditional** movement block (independent of player/technology).
  However, geometric adjacency still exists (for adjacency effects).
- Flag in data: `isSupernova`.
- Source: TI Wiki /wiki/Anomalies.

### 1.4. Gravity Rift — ✅ VERIFIED
- A ship that **exits** or **passes through** a gravity rift: **+1 to move value** — once per distinct rift; exiting the same rift again gives no further +1 but rolls again (R_gravity_rift rules-reference (TE) + notes/2).
- Upon exiting a gravity rift: roll a die; a result of **1-3 destroys** the ship.
- Code takeaway: movement modifier (+1) and destruction risk — does NOT block adjacency.
- Flag in data: `isGravityRift`.
- Source: TI Wiki /wiki/Anomalies.

### 1.5. Entropic Scar (Thunder's Edge) — ✅ VERIFIED
- Anomaly with no effect on movement. Flag in data: `isScar` (tiles `114` Entropic Scar, `116` Lemox).
- Unit abilities — Sustain Damage, Production, Planetary Shield, Space Cannon, Bombardment,
  Deploy, Anti-Fighter Barrage — do not work THROUGH units in an entropic scar or AGAINST them.
  Text abilities (factions, technologies, cards, flagships) work normally; text dependent on
  a unit ability (X of Dock II) does not work.
- A wormhole token that would be placed in an entropic scar returns to the supply/reinforcements.
- Start of status phase: a player with SHIPS in an entropic scar may spend a command token from their strategy pool to gain
  one of their faction technologies (ignoring prerequisites); ships in two entropic scars = two tokens
  and both technologies. Ground forces do not count.
- ✅ User decision (2026-11-28) (Deploy): DEPLOY cannot place/replace a unit IN an entropic scar (Letani Behemoth,
  Dunlain Reaper, Scavenger Zeta, ZS Thunderbolt M2) — the unit after using the ability would be
  in the entropic scar.
- ⚠️ ASSUMPTION (Ion Storm): the Ion Storm token is a frontier token with a wormhole, not a "wormhole token" —
  it stays in the entropic scar. No ruling; to be confirmed.
- Code: `core/entropic_scar.py` (single query "is entropic scar"), central hooks: `battle.sustain_denied`,
  `battle.combat_units` (AFB), `space_cannon`, `invasion` (shield, bombardment),
  `combat_bombardment`, `production.producers`; status phase offer `core/hooks/entropic_scar.py`.
- Source: TE rule text from AsyncTI4 assets (`assets/data/rules/thundersedge.json` — `entropicScar`);
  tirules2 [R_entropic_scars](../../../../rules_tirules/R_entropic_scars.md).
