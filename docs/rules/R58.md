## 58. Player Chess Clock — ⚠ ASSUMPTION (design feature, NOT a TI4 rule) — user decision 2026-11-11

Source: user request (2026-11-11): "each player's timer — how much total time they have and how much has elapsed in the current
turn, like in chess; configured in Settings on the home page". TI4 has no clock rule.

**58.1 Configuration.** Settings → "Chess clock" (frontend: `appStore.chessClock*`): toggle, minutes pool per player
(1–1440), increment in seconds per turn (0–3600). Sent in `POST /game/new` as `chess_clock`
(`{total_minutes, increment_seconds}`; omitted = game without clock). In a running game: Settings → "Current game"
(`POST /clock/configure` — start/restart, everyone gets the full pool from now; `POST /clock/disable` — disable).
The clock bar sits in the map view (`PannableMapView`), draggable (`useDraggablePanel`).

**58.2 Whose clock ticks (`core/game_clock.clock_holder`).** ⚠ ASSUMPTION: whoever is deciding NOW:
the current respondent of an open timing window (secondary, casualties, space cannon, reactions); otherwise
`active_player_id` (strategy card pick, action phase turn, status scoring, agenda voting).
During initial setup (parallel choices) and after game end, the clock is stopped.

**58.3 Turn and increment.** "Turn time" = an uninterrupted sequence of decisions by a single holder (changing holder resets the counter).
⚠ ASSUMPTION: a player receives the (Fischer) increment when `active_player_id` passes from them to someone else
(end of their turn) — responding in a window (e.g., secondary) does not grant an increment.

**58.4 Time expiration.** ⚠ ASSUMPTION: the engine does NOT penalize time expiration (no forfeit / auto-pass) —
time goes below zero and the UI displays it in red. Penalty is up to the user's discretion.

**58.5 Pause.** `POST /clock/pause` / `POST /clock/resume` (no `actor_id` — this is a table matter, not a game action;
any player may trigger it). Button in the clock bar.

**58.6 Mechanics and limitations.** State: `GameState.clock` (`GameClock`), mutated only by `core/game_clock.py`.
Time is settled on every commit (`StateService.replace_state` → `game_clock.settle(now)`), time source
injected (`create_app(now=...)`, deterministic tests). Web-data: `chessClock` (values at document build time);
UI (`domains/clock/ChessClockPanel`) adds elapsed time since RECEIPT, so clock skew across computers
does not matter. ⚠ Undo/Redo restores the snapshot together with the clock (time "rewinds" to that moment, and the interval since
then is charged to that snapshot's holder) — acceptable for a God-Mode escape hatch.
