## 4. Stat-Area Positions (player-stats hexes) — ✅ VERIFIED (AsyncTI4 algorithm port)

📎 tirules: [Game Board](../../../../rules_tirules/R_game_board.md) · [Command Sheet](../../../../rules_tirules/R_command_sheet.md) · [Victory Points](../../../../rules_tirules/R_victory_points.md)

The colored "player stats" hexes beside the board are a **contiguous triplet of empty tiles**
near the player's home slot. Algorithm (PORT, not from memory) from AsyncTI4 source:
`TI4_map_generator_bot/.../PlayerStatsHelper.findThreeNearbyStatTiles`:

1. Candidates = EMPTY positions (no system), ring ≤ `ringCount+1`, not occupied
   by another player (shared `taken`).
2. Pick closest ones (distance to home slot + ring penalty) until a
   contiguous triplet is formed (one tile is adjacent to the other two).
3. Return `[pivot, neighbor, neighbor]` — **pivot (middle) FIRST**.

Order matters: the frontend assigns `firstHex` = faction identity (art,
name, strategy cards, secrets, **VP**), `secondHex` = command tokens (CC),
`thirdHex` = trade goods / commodities / action cards + ACTIVE/PASSED status
(source of roles: `frontend/.../PlayerStatsArea.tsx`). Therefore the pivot (middle hex) must
be first — that is where the faction emblem belongs.

Implementation: `src/api/web_data.py` → `_three_nearby_stat_tiles` / `_build_stat_tile_positions`.
Distance in cubic metric (pixel proxy from the original). Verified 1:1 against a live
AsyncTI4 game and for 6 players (18 unique positions, no overlaps).
