## 34. Component Timing Specification: Trigger → Window Type — ⚠ ASSUMPTION (D10)

📎 tirules: [Action Cards](../../../../rules_tirules/R_action_cards.md) · [Abilities](../../../../rules_tirules/R_abilities.md)

Implementation: `src/core/timing_spec.py` (`TriggerKind`, `TimingSpec`, `parse_timing`,
`TRIGGER_WINDOW_MAP`); spec `local-ti4-data-foundation`, R8.

**Verified (data):** window phrases (`window` for action cards and faction abilities,
`abilityWindow` for leaders) are read from AsyncTI4 JSON and classified solely by
prefix: `when ` / `after ` / `before ` / `instead of` / `at the start` / `at the end` /
`during ` / `action`; everything else → `unclassified`. Window text remains unchanged (`raw_text`).
`playTiming` (`AGENDA_WHEN`/`AGENDA_AFTER`) is used only to verify window compatibility.

**⚠ ASSUMPTION (pending user confirmation):** mapping trigger kind to engine
`WindowType`: `when`, `after`, `before`, `instead` → `REACTION`; `at_start`,
`at_end`, `during`, `action`, `unclassified` → "no window" (`None`). This is a design
decision (D10), not a TI4 rule — e.g., "at the start of..." may require its own
window in the future. Changing it = editing a single `TRIGGER_WINDOW_MAP` table + test.
