## 35. Reference Consistency: `<color>` Placeholder in Promissory Notes as TEMPLATE — ⚠ ASSUMPTION

📎 tirules: [Promissory Notes](../../../../rules_tirules/R_promissory_notes.md)

Implementation: `src/core/references.py` (`find_unresolved_references`,
`build_reference_report`, `UnresolvedReference`, `TemplateReference`); wired into
`StaticDataRegistry` (`reference_report`, `unresolved_references()`). Spec
`local-ti4-data-foundation`, R7.

**Verified (data):** consistency checking reads ONLY identifiers from AsyncTI4 JSON
(faction lists: `leaders`, `abilities`, `promissoryNotes`, `factionTech`,
`units`, `startingTech`, `startingTechOptions`; `cardIDs` of canonical decks;
`attachmentId` of explorations; `attachmentID` of tokens) and compares them against the
Component Catalog and registry dictionaries. The existing systems → planets check
(`missing_planet_references`) is preserved. A target that exists but comes from a
non-canonical source is flagged with `leaks_noncanonical` (homebrew leak, R7.6), detected by
`LoadReport.skipped_index`.

**⚠ ASSUMPTION (pending user confirmation):** promissory notes from `color.json`
have an identifier containing the `<color>` placeholder (e.g., `<color>_cf`,
`<color>_sftt`). These are TEMPLATES — one card per player color, not a concrete
component. Adopted behavior: any reference whose identifier contains `<color>` is
reported SEPARATELY as a "template" (`ReferenceReport.templates`) and is NOT counted
as an unresolved reference (excluded from `find_unresolved_references`).
Reference matching uses the literal `id`, without expanding the color. This is a design
decision (design R7, `core/references.py` section), not a TI4 rule — to be confirmed
after the first Data Auditor report. Changing it = expanding the template to real player
colors (a separate step) or handling it differently in `references.py`.
