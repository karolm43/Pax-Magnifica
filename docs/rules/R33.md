## 33. Activation and production validation (strict enforcement) — ✅ VERIFIED (LRR 2.0)

Milestone E8-T6. Source: local LRR 2.0 — `docs/rules_tirules/R_active_system.md`,
`R_production.md`, `R_producing_units.md` (content © FFG; see SOURCE.md). Completes action phase
enforcement outside combat (RULES.md 29.1). Numeric data (cost, production) from UnitDef/registry.

### 33.1. System activation (R_active_system) — ✅ VERIFIED

- A player CANNOT activate a system that already contains THEIR OWN command token.
- A player MAY activate a system containing OTHER players' tokens.
- Activation places a token from the TACTIC pool (`PlayerState.tactical_cc`) — requires ≥1 token.

**Enforcement (strict, `ValueError` → 422):** `tactical.activate_system` checks:
- there is an active player (existed);
- player has ≥1 token in tactic pool (previously only decremented "if >0", now STRICT);
- system does NOT already contain the player's own token (new).
God-Mode (`board_edit.place_command_token`) still bypasses (correction without spending pool).

**33.1a. Turn referee on activation (audit 2026-11-11; R_action_phase, RULES.md 31.7):**
non-`free` activation is a turn action just like strategic and component actions, so it
additionally requires: ACTION phase, no open timing window (`pending_window`), no multi-step
primary (`pending_strategy`), and a player who has not passed. Previously a system could be
activated during strategy/status/agenda or during a secondary window (in Fleet Logistics).
`free=True` (Warfare TE) skips these checks — the strategy card handles them.

### 33.2. Production: cost and limit (R_production, R_producing_units) — ✅ VERIFIED

- **Cost (R_producing_units):** to produce a unit, the player spends resources ≥ its cost.
  Resources come from planets (exhausting) and the player's trade goods. Excess is lost. For
  multiple units, costs add up.
- **Dual production:** fighter/infantry = 2 units for one cost; 1 may be produced, but full cost
  is paid. Each unit counts toward the LIMIT.
- **Production limit (R_production):** a player may produce a number of units ≤ the sum of
  `Production` values of their units in the active system (space docks/units with PRODUCTION).
  Fighters/infantry count 1 per unit toward the limit.
- **Ship blockade (R_producing_units):** SHIPS cannot be produced in a system with enemy ships;
  ground forces can.

**⚠️ SCOPE OF T6 (intentional skeleton — option "b", agreed with user):**
- **Cost: we enforce CHECKING, without actual spending.** The engine computes available budget
  (sum of `resources` of READY planets of the player + `trade_goods`) and REJECTS a production
  order exceeding the budget. It does NOT exhaust planets or deduct TG — actual spending will
  arrive with the influence model (the same one that will unlock Leadership secondary from T3).
  Marked TODO.
- **Production limit: enforced STRICTLY** — sum of PRODUCTION values of the player's units in
  the active system (from UnitDef — `production_value`). Fighters/infantry count individually.
- **Ship blockade: enforced STRICTLY** — ships rejected when enemy ships are in the active
  system; ground forces/structures allowed.
- Placement (ship→space, ground→planet) is already enforced on placement (RULES.md 26); here
  budget + limit + blockade are added. Choosing specific planets for ground forces = as before
  (God-Mode edit places; auto-control RULES.md 23).
- Actual planet/TG spending + "remove from board to place from reinforcements" (component
  limitations) = TODO (expansion with influence and reinforcements model).

**Model and implementation:**
- `core/production.py` (NEW): `production_limit(state, grid, registry, player_id)` (sum of
  PRODUCTION in active system), `available_budget(state, registry, player_id)` (ready planets + TG),
  `validate_production(...)` (cost ≤ budget, count ≤ limit, ship blockade) → `ValueError`.
  Called by the production endpoint BEFORE placing units (God-Mode edit remains as execution).
- Pure functions. God-Mode (`/system/{pos}/edit-units`) STILL bypasses (no-rules valve).

**Status:** ✅ T6 activation (own CC + pool) + production (budget-check, limit, ship blockade).
Actual spending and reinforcements — see 33.3 (✅ done, with one exception described below).

### 33.3. PRODUCTION step completed: payment, shared limit, zones, reinforcements — ✅ VERIFIED

📎 tirules: [Production](../../../../rules_tirules/R_production.md) · [Producing Units](../../../../rules_tirules/R_producing_units.md) · [Cost](../../../../rules_tirules/R_cost.md) · [Component Limitations](../../../../rules_tirules/R_component_limitations.md) · [Blockaded](../../../../rules_tirules/R_blockaded.md)

Replaces "option b" from 33.2. `core/production.produce(...)` (endpoint `POST /tactical/produce`):
- **REAL payment:** chosen planets are exhausted (`exhausted_planets`), TG are deducted from pool;
  planets must be controlled and ready; payment ≥ cost, excess is lost. Omitted `spend` →
  `auto_pay` (largest planets first, unnecessary ones dropped, TG only for remainder — for bot).
- **Pair cost:** AsyncTI4 data stores cost PER UNIT (fighter/infantry = 0.5); the card says
  "1 for two". Pair = 2 × unit cost, N units = ⌈N/2⌉ pairs, counted across the type as a whole
  (infantry on two planets is still one pair). Earlier code charged half price — fixed.
- **SHARED limit for the action:** `GameState.production_used` (reset on activation/end of action);
  subsequent orders in the same step count toward the same PRODUCTION limit.
- **Zones (R_production):** ships → only space of active system. Ground forces → planets with a
  PRODUCTION unit (space dock); when a unit in space produces — also any planet of the player
  in the system or space itself (`allowed_ground_zones`).
- **Reinforcements (R_component_limitations):** types other than fighter/infantry are limited
  by plastic (`UNIT_CAP_BY_ASYNC_ID`); none in reinforcements → rejected.
- Window view: `GET /tactical/production/view` (limit, used, producers, zones, planets, TG,
  units with reinforcements). Frontend: `frontend/src/domains/production/` (window opens
  automatically in the step).

**Separate PRODUCTION abilities (R_production) — ✅ VERIFIED:** each unit with PRODUCTION is a
separate source (`Producer`: zone, type, `per_unit`, `value`, `forbids`). Values ADD UP to the
limit, but type restrictions are per source. Arborec: "Production value from Arborec space docks
cannot be used to produce infantry" — space dock (`("arborec","spacedock")` → `forbids=("infantry",)`)
cannot produce infantry; Letani Warrior infantry has its own PRODUCTION 1 (II: 2) per unit and
produces any type. Validation = Hall's condition (`fits_producers`) on ACCUMULATED units of the
action, so order of requests does not matter. `GameState.production_placed` (zone→type→count)
tracks what was built in the action; freshly produced units do NOT add PRODUCTION in the same
step (producers = pre-step state). View: `producers[].perUnit/forbids`, `usedByType`, `units[].onBoard`.

⚠️ ASSUMPTIONS / gaps (pending user decision): (1) ✅ "remove unit from board to place from
reinforcements" (R_component_limitations) works in production: `ProductionOrder.sources` + chips
in the production window (RULES.md 63.1); (2) Arborec space dock restriction currently lives in
the `_PRODUCTION_FORBIDS` table (eventually faction hook, E7); (3) cost/limit modifiers from
cards and technologies (E7) omitted; (4) ground placement is not tied to a specific producer
(a planet with any PRODUCTION ability accepts units from any producer in the system — per the
R_production example).

**Planet of a producer that produces nothing (F_arborec Mitosis/1, Letani Warrior/3) — ✅:**
ground forces may be placed on a planet with a producer that itself cannot produce them
(Arborec space dock + infantry) only if that producer produced at least 1 unit in this action:
"If the Arborec player produces one or more units with a space dock, and produces any infantry
with their Letani Warriors, the produced infantry may be placed on the same planet as the space
dock". Validation: assign 1 unit of a type allowed by that planet's producer to each such
planet, and check Hall's condition for the rest (`production._check_idle_producer_zones`).
A producer in space (any owned planet) and "produce" grants (flagship, commander, hero) —
without this condition.
