## 19. Tactical Action: System Activation + Step State Machine — ✅ VERIFIED (AsyncTI4 bot)

📎 tirules: [Tactical Action](../../../../rules_tirules/R_tactical_action.md) · [Active System](../../../../rules_tirules/R_active_system.md) · [Command Tokens](../../../../rules_tirules/R_command_tokens.md) · [Movement](../../../../rules_tirules/R_movement.md) · [Invasion](../../../../rules_tirules/R_invasion.md) · [Producing Units](../../../../rules_tirules/R_producing_units.md)

> ⚠️ **DIRECTION UPDATE (see Section 29):** annotations `does NOT validate` / `assistant, not a referee` in this section are SUPERSEDED. The content remains accurate as a REFERENCE for TI4 mechanics; rule enforcement moves into `core/` per 29.1.


Stage E3. **Design decision (agreed with user):** the application GUIDES the player
through the tactical action steps, but **does NOT validate TI4 rules** — players play physically
(tabletop) and enter the outcome. The engine is a table assistant, not a referee. Therefore, the
rules below serve as a TI4 REFERENCE; enforcement (movement legality, range, fleet supply) is handled by the operator.

**Tactical action step sequence** (action phase timing windows), source: AsyncTI4
`service/tactical/` + LRR: `ACTIVATION → MOVEMENT → SPACE_CANNON (offense) → SPACE_COMBAT →
INVASION → PRODUCTION`. Model: `GameState.tactical_step` (enum `TacticalStep`), `active_system`
(position of the activated tile). State machine: `core/tactical.py` (`activate_system`, `next_step`,
`set_step`, `end_tactical_action`).

**System activation** (source: `CommandCounterHelper.addCC` with `useTactic=true`, `Tile.addCC`
→ `Space.ccList`, `Game.setActiveSystem`):
- The active player places a **command token** in the system's **space** area —
  model: `SystemState.command_tokens: list[player_id]`. The token is taken from the player's
  **tactic pool** (`PlayerState.tactical_cc`, decremented by 1).
- `active_system` is set; the state machine starts at `MOVEMENT` (activation is step zero).
- **TI4 rule (reference only, NOT enforced):** you cannot activate a system that already
  contains YOUR command token (AsyncTI4 `ButtonHelper.canActivateTile`:
  `!hasCC(player.color, tile)`). Here the operator enforces this; `activate_system` is
  idempotent (does not duplicate the token) and does not block.
- The token **remains** on the system after the action ends (as on the tabletop) — `end_tactical_action`
  only clears `active_system`/`tactical_step` and does not remove CCs.

**Control vs tokens (confirmed in AsyncTI4):** a command token (`command_tokens` /
`Space.ccList`) is INDEPENDENT of control. SPACE control is not a separate field —
it derives from ship presence (`space_units`). PLANET control is explicit `planet_owners[planet]`
(single owner; `UnitHolder.addControl` clears the predecessor). A state where "player A controls
the planet while player B holds space/has a token" is legal and representable (see RULES.md 2b/12).

**God-Mode:** `board_edit.place_command_token` / `remove_command_token` allow the operator to
manually adjust tokens (without spending from the pool — this is an adjustment, not an activation).

### 19.1. Guided step entry (auto-open) — ✅ VERIFIED (LRR 2.0, R_tactical_action)

Source: `R_tactical_action` — step 3 "If two players have ships in the active system, those players
**must** resolve a space combat"; step 4 the active player **may** bombard and commit ground forces;
notes/1 "each of these five steps happen during every tactical action, unless explicitly skipped".

- **Next step** (`tactical.advance_guided`, used by `POST /tactical/step/next` AND the bot engine's
  `tactical_next`): `advance_skipping_empty` + `auto_open_step`, ONE step / one settle.
- Entering **SPACE_COMBAT** with a mandatory combat starts it at once (`battle.start_combat`) -
  no "Start space combat" click (the combat is mandatory, there is nothing to decide).
- Entering **INVASION** with something to bombard or land begins it at once (`begin_invasion`).
- The history label names the opened event (`battle:start:space` / `invasion:begin`), so the
  Activity feed shows it like a manual start; otherwise `tactical:step`.
- Auto-open waits when it cannot start yet (open timing window, reaction pause, held play): the
  step is entered without the window and the player starts it by hand (fallback button stays).
- **Skip invasion** (`tactical.decline_invasion`, `POST /tactical/invasion/skip`): bombardment and
  commit are both optional ("may"), so the active player can close an auto-opened invasion
  without doing anything (Bombardment -> Commit nothing -> Establish -> closed). Refused once
  ground forces were committed, or when a contested planet forces ground combat (RULES.md 40.1 I7a).
- PRODUCTION: backend unchanged (production is optional, step 5 "may"); the UI opens the
  production window on step entry.
