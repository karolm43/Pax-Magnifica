### 38.1. Rules (Space Cannon Offense)

- **(S1) After movement, before combat.** After the Move Ships step, each player MAY use the Space Cannon
  ability of their units in the ACTIVE system. Applies even if nobody moved ships.
- **(S2) NOT only the active player.** "A player is **not** required to be the active player". Order:
  the ACTIVE player goes first, proceeding CLOCKWISE (`seating_order` rotated so the active player is
  first). This is a timing window (`WindowType.SPACE_CANNON`, RULES.md 29.2), not an active player's move.
- **(S3) Targets.** Players other than the active player MUST target the active player's units. The active
  player, using their own units, CHOOSES a player who has ships in the active system. A player with no
  legal target (nobody to hit) is skipped in the queue.
- **(S4) Roll.** One roll (d10) per die of each unit with Space Cannon in the active system
  (ships in space AND structures/units on planets of that system). Hit = result ≥
  `spaceCannonHitsOn`. Dice = `spaceCannonDieCount` (missing value = 1 die). "0" on d10 = 10.
  Effects that modify/reroll combat rolls do NOT apply to space cannon rolls.
- **(S5) All or nothing.** A player using Space Cannon must use it for ALL of their
  eligible units (including adjacent ones — S6).
- **(S6) Range — Deep Space Cannon.** A unit with Space Cannon in a system ADJACENT to the active system
  (graph adjacency, `R_adjacency`: geometry + wormholes) fires ONLY if that player's UNIT VARIANT
  has `deepSpaceCannon`. The variant depends on the player's technologies: PDS I
  (`spaceCannonHitsOn=6`, no deep) → PDS II (tech `pds2`: `5`, `deepSpaceCannon=true`). Hits
  still hit units in the ACTIVE system. The variant is selected by `combat.resolve_unit_variant`
  (faction-upgraded > … > generic-base), not a hardcoded list of technologies.
- **(S7) Assigning hits.** The targeted player destroys one of THEIR ships in the active system for
  each hit (including fighters). They cannot assign hits to another player's units.
  Number destroyed = min(hits, count of their ships in the system).
- **(S8) Order within the window.** Losses are resolved after a player's roll before
  the next player rolls.

### 38.2. Map Preview Range ("Space Cannon range")

The map lens shows which systems are UNDER FIRE: for each tile and each player, it counts
units with Space Cannon in that tile (directly) plus units with `deepSpaceCannon`
in adjacent tiles. The result goes to web-data as `tileUnitData[pos].pds[faction] = {count,
expected}` (a contract the AsyncTI4 frontend already renders); `expected` = Σ dice × (11 − hitsOn)/10.

### 38.3. Implementation

- `core/dice.py` — seedable d10 roll stored in game state (`GameState.rng_seed/rng_counter`),
  making Undo/Redo deterministic. Shared foundation for combat (Block C).
- `core/space_cannon.py` — shooters, coverage, queue, `open_offense`/`fire`/`pass`/`assign_hits`.
- `api/routers/space_cannon.py` — `GET /tactical/space-cannon`, `POST …/fire`, `…/pass`, `…/assign`.
- Entering the SPACE_CANNON step (`/tactical/step/next`) opens the window automatically; leaving the step
  is blocked (422) while the window remains open.
- After the last player, the window closes, but the resolution log (rolls, hits, losses) remains
  in `GameState.space_cannon_log` until the end of the tactical action — the panel displays the result (`resolved`).
