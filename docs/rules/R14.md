## 14. Data Sources: Codexes + thunders_edge, Errata Dedup — ✅ VERIFIED (data)

📎 tirules: [Technology](../../../../rules_tirules/R_technology.md) · [Technology (Components)](../../../../rules_tirules/C_technology.md) · [Breakthroughs](../../../../rules_tirules/R_breakthroughs.md)

Source: AsyncTI4 technology data (`assets/data/technologies/*.json`), verified
2026-10 on the loaded registry.

**Active sources (`enabled_sources.json`):** `base, pok, codex1, codex2, codex3, codex4,
thunders_edge`.

**Finding (refutes earlier assumption):** `thunders_edge` **does NOT include** changes
from the codexes. It adds 13 completely new technologies (without `homebrewReplacesID`), rather than
building on top of errata. Official errata (Ω/ΩΩ) exist ONLY in `codex1`/`codex4`:
- X-89 Bacterial Weapon: `x89_base` (base) → `x89` ΩΩ? no — `x89` (codex1, Ω) →
  `x89c4` (codex4, ΩΩ, latest).
- Magen Defense Grid: `md_base` (base) → `md_c1` (codex1, Ω) → `md` (codex4, ΩΩ).

Therefore, codexes MUST remain enabled — without them the game would use older (incorrect)
versions of X-89 and Magen Defense Grid.

**Errata dedup (God-Mode technology picker):** variants of the same card (base/Ω/ΩΩ)
have different names (Ω/ΩΩ suffix), so deduplication by name did not collapse them. Rule:
- Family key = card name with the Ω/ΩΩ marker and whitespace stripped.
- For each family, keep the variant with the highest source priority:
  `codex4 > codex3 > codex2 > codex1 > {pok, thunders_edge} > base`.
- Ω/ΩΩ marker = official indicator of a subsequent erratum (AsyncTI4 data).
Implementation: `frontend/.../PlayerEditorModal.tsx` (`techFamilyKey`, `SOURCE_PRIORITY`).

**Source priority (highest first):** `thunders_edge > pok > codex4..1 > base`
(sources outside the list = homebrew, lowest priority). When multiple enabled sources
provide a variant of the same component (e.g., Construction/Warfare strategy cards),
the variant from the HIGHEST enabled source (Thunder's Edge) takes precedence. This is a deliberate
user design decision (all expansions enabled, Thunder's Edge takes precedence) — Thunder's
Edge reworks Construction (4) and Warfare (6), so its variants `te4construction` /
`te6warfare` supersede `pok4construction` / `pok6warfare`.

**Artwork — purely visual fallback:** when the highest-priority source's variant lacks an image
asset (`imageURL: ""`, as is the case for `te4construction`/`te6warfare`), the UI uses the artwork
of a variant with the same initiative from a lower source (e.g., `ConstructionProphecyOfKings.webp`
from `pok4construction`, `Warfare.webp` from `pok6warfare`). Content and parameters (name, texts,
initiative, color) REMAIN from the highest-priority source variant — the fallback applies exclusively
to the image. When no variant has artwork, the UI provides a text fallback.
Implementation: `frontend/src/entities/lookup/strategyCards.ts`
(`SOURCE_PRIORITY`, `sourceRank`, `withImageFallback`).

**Strategy card set selection — rule in CORE (not on the frontend).** The engine selects the
canonical strategy card set according to the HIGHEST enabled source (priority
`thunders_edge > pok > codex4 > codex3 > codex2 > codex1 > base`; sources outside the list =
homebrew are ignored for this selection). With Thunder's Edge enabled, the TE set applies
(alias `te`): Construction=`te4construction`, Warfare=`te6warfare`, remaining
PoK cards; without TE — the `pok` set (`pok4construction`/`pok6warfare`); down to
`base_game`. When no standard set matches (only homebrew/empty sources) —
safe fallback to `pok`. The rule lives in `core/registry.active_strategy_card_set_alias`
(a pure function over enabled sources), and `strategy_card_set()` without an explicit alias
returns the canonical set. As a result, `/strategy/cards` and web-data return canonical
variants (te4/te6 with TE) independently of the frontend — the frontend only renders. Source
priority is identical to technology errata dedup (above). Semantic review finding #5
(backend part).
