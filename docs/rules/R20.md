## 20. Combat: Numerical Helpers (Assistant, Not a Referee) — ✅ VERIFIED (UnitDef data)

Stage E3. **Design decision:** the application does NOT resolve combat — it does not roll dice or
assign hits. Players do that physically on the table; the application only provides numerical
HELPERS and a convenient window to subtract destroyed units (via God-Mode edit-units).

**Combat stats** read from `UnitDef` (registry, zero from memory): `combat_hits_on`
(hits on X+), `combat_die_count` (dice per unit). Units without these fields (PDS, Space Dock)
do NOT participate in space combat — skipped (PDS has a separate `spaceCannonHitsOn`, a different
mechanic). Expected hits for a group: `count * die_count * (11 - hits_on) / 10`.

**Player unit variant resolution** (`core/combat.resolve_unit_variant`): for a given
`base_type`, we select the variant by priority: faction-upgraded > faction-base >
generic-upgraded > generic-base. An upgrade counts only when the player has the required
technology (`required_tech_id`). Consistent with unit selection rules in web-data (RULES.md 10),
so stats in the combat window match the player's actual units (e.g., Sol upgraded
carrier, faction flagship 5+/2 dice, War Sun 3+/3 dice).

**Combat detection:** `space_combat_participants` (ships in space) / `ground_combat_participants`
(ground forces on a planet) return sides ONLY when combatants ≥ 2 (otherwise no combat).
Forces are counted from `space_units` / `planet_units` (space control = ship presence, RULES.md 19).

**UI flow:** "Combat" button in the tactical panel (when the active system has ships from ≥ 2
players) → `GET /tactical/combat/{pos}` → modal with two sides, unit list + helpers
(dice, X+, expected). Subtracting destroyed units = `edit-units` delta -1 (God-Mode).
