## 25. Drag-and-drop unit movement (UI/God-Mode) — ✅ DESIGN DECISION

📎 tirules: [Transport](../../../../rules_tirules/R_transport.md) · [Movement](../../../../rules_tirules/R_movement.md) · [Units](../../../../rules_tirules/R_units.md) · [Capacity](../../../../rules_tirules/R_capacity.md)

This is a UI CONVENIENCE mechanic, not a TI4 rule — moving without rule validation
(assistant, not referee). You drag a unit sprite from a tile/zone onto another tile or
planet; for stacks (>1 unit, e.g., infantry `gf`, fighters `ff`, mechs `mf`), upon drop a
prompt asks "how many to move" (1 / half / all / custom count), while a single unit moves
immediately.

**How it works (conventions, not rules):**
- The map scrolls via the `dragscroll` library, which binds a NATIVE `mousedown` (bubbling)
  listener on the `.dragscroll` container and starts panning there. React `stopPropagation`
  does not stop that, so we intercept unit drag start with OUR OWN native listeners in the
  CAPTURE phase on the sprite (`mousedown`/`touchstart`) calling `stopPropagation` — the event
  never reaches dragscroll, so grabbing a unit does NOT pan the board. A movement threshold
  (`DRAG_THRESHOLD=8px`) distinguishes dragging from clicking (short move = click → dossier).
  The unit ghost is rendered via a portal to `document.body` (the map has `transform: scale`,
  which would break `position: fixed`).
- The unit tooltip (hover) is HIDDEN while dragging — the `appStore.isDraggingUnit` flag
  (set once the threshold is crossed) suppresses showing the tooltip and clears any existing
  one (otherwise it would obscure the map during the gesture).
- Native text/image selection and HTML5 image-drag are DISABLED (otherwise dragging would
  highlight sprites/tiles "like a browser image" and lose the gesture): statically via
  `.draggable` + `.draggable img` (`user-select:none`, `-webkit-user-drag:none`), strictly
  via `dragstart`→`preventDefault` on the sprite, and globally via `body.dragging-unit`
  (`user-select:none !important`) during active dragging.
- Drop target from DOM under cursor (`elementFromPoint`): tile = `id="tile-<position>"`,
  planet = `data-search-key="planet:<id>"`. Target zone = planet name or `"space"` (orbit),
  consistent with `stackHolder(stack) = planetName ?? "space"` and the `/units/move` contract
  (RULES.md: `from_zone`/`to_zone` = `"space"` or planet ID).
- The move is executed by the existing `POST /units/move` endpoint (`board_edit.move_units`) —
  clamps `count` to available units, recomputes planet control on planet entry/exit
  (RULES.md 23). Commit → history (Undo works).

Implementation: `frontend/.../hooks/useUnitDrag.ts` (pointer events + ghost + target detection),
`UnitStack.tsx` (hooks on sprite/badge), `UnitDragGhost.tsx` (ghost), `MoveQuantityModal.tsx`
("how many to move" prompt), `appStore.unitDrop` (prompt state). DnD active only for real
units outside history playback (replay).
