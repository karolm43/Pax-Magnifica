### 36.1. Hand Limits (TI4 Rules) — ✅ VERIFIED

Primary source: tirules2.com (local dump `docs/rules_tirules/`). Overarching rule:
the limit may be modified by game effects (cards/technologies) — base limit below.

| Hand | Limit | Source (tirules) | Clarification Quote |
|---|---|---|---|
| Action cards | **7** | [R_action_cards](../../../../rules_tirules/R_action_cards.md) | "Each player's hand can have a maximum of seven action cards." + "A game effect can increase or decrease the number of cards a player's hand can have." |
| Secret objectives | **3** (total scored + unscored) | [R_objective_cards](../../../../rules_tirules/R_objective_cards.md) | "Each player can have up to three total scored and unscored secret objectives." (excess → return to deck) |
| Promissory notes | **no limit** (`null`) | [R_promissory_notes](../../../../rules_tirules/R_promissory_notes.md) | Rules do NOT specify an upper hand limit for promissory notes. A player starts with 6 of their own (1 unique + 5 generic), which are given to others; "The number of promissory notes in a player's hand is public information", with no cap. |

Note on secret objectives: the "3 total" limit applies to scored + unscored.
In the model (`PlayerPrivateState.secret_objectives`), we currently store only UNSCORED ones
(in hand). Enforcing the limit including scored ones will be added when secret
objective scoring mechanics are built. Until then, `secret_objectives = 3` serves as the
hand limit for unscored objectives (compliant with the rule as an upper bound).

Asset entry (`assets/config/engine_config.json`):
```json
"hand_limits": { "action_cards": 7, "secret_objectives": 3, "promissory_notes": null }
```
`null` = no upper limit (not imposed by the rules).

### 36.2. Bot Difficulty Set — ⚠️ ASSUMPTION (pending user confirmation)

Bot difficulty levels **do NOT exist in TI4 rules** — this is a concept of our AI layer
(checked: no "difficulty" in AsyncTI4 assets or in the tirules dump). In line with the
project principle, we do not hardcode the set in code: it is a CONFIGURABLE value read
from `engine_config.json` via `StaticDataRegistry.valid_difficulties()`.

Proposed starter set (⚠️ ASSUMPTION): `["EASY", "NORMAL", "HARD"]`.

**User decision requested:** is this set appropriate, or do you prefer another
(e.g., adding "VERY_HARD"/"INSANE", using Polish labels, or a numeric 1–5 scale)? The set
can be changed solely by editing `assets/config/engine_config.json` — with no code changes.
Until confirmed, we treat this set as a temporary assumption.
