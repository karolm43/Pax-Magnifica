## 54. Event and timing window database (event engine) — ✅ VERIFIED (tirules R_abilities) / ⚠ ASSUMPTIONS

Goal: cards, factions, agendas, relics, and technologies are added as HOOKS ON EVENTS, without touching base rules.
Full timing window catalog of all components: `docs/OKNA_CZASOWE.md` (GENERATED: `uv run python -m src.audit.timing_catalog --write`).

**54.1 Model.** Window = (`GameEvent` event, `Moment` moment) pair + context filters. Events and window text classifier: `core/game_events.py` (~66 events; `EVENT_INFO.emitted_by` states which engine function emits it, a test enforces consistency with code). Emission: `triggers.fire(state, event, moment, subject=..., ctx=...)`. Hook registration: `@rules_hooks.on_event(event, moment, source, kind=..., optional=..., where=...)`.

**54.2 Order and mandatoriness (R_abilities).** All "when" before "after"; action phase = initiative order starting from active player; strategy/agenda = clockwise from speaker. An ability is mandatory unless it says "may" — then a `PendingOffer` and `REACTION` window are created (players one by one). REPLACE ("instead", "would") has priority and ends event resolution. Emission nesting limit: 12.

**54.3 Persistent effects.** `ActiveEffect` (`GameState.active_effects`), modified EXCLUSIVELY via `core/active_effects.py`. Scope (`Duration`): turn, tactical_action, combat, combat_round, invasion, agenda, phase, round, game. Expire on scope-end events (`triggers.EXPIRY`). An effect with a duration remains if the component disappears. Hook source: `HookSource(effect, key)`.

**54.4 Hook sources.** Faction (abilities, leader depending on state, breakthrough once unlocked), technology, relic, law (agenda), persistent effect. Cards in hand (action cards, hidden promissory notes) are NOT sources and do not create offers (STOP, 43.4). Static data registry is bound globally (`rules_hooks.bind_registry`).

**54.5 Analysis results** (740 components, 123 agendas: absol×60, base×50, pok×13): window patterns, durations, and special cases are in `OKNA_CZASOWE.md`, sections 2–9. Action cards, relics, promissory notes, exploration, events, abilities, and leaders have `window` fields; agendas, technologies, and breakthroughs have windows only in text (heuristic classifier). Special cases remain (e.g., hack, titansbt, yssarilbt) — handled manually during implementation.

**54.6 Hooked emissions** (wave 1–2): turn/pass/phase/round, status→agenda, activation/movement/tactical action, production, planet control, technology research and gain, card draw, component/action card, agenda (reveal, votes, outcome, law), combat (start/end, round, roll, hits, sustain, AFB, win), unit destruction/placement, space cannon, invasion (bombardment, defense, commit), strategic action and strategy token, setup, relic/breakthrough/promissory note gain, TG/commodities, strategy card pick (with REPLACE), speaker, transactions. Events defined but not yet emitted have `emitted_by=None` (list in `OKNA_CZASOWE.md` §2).

**54.7 ⚠ Assumptions/simplifications (to be confirmed).** (a) The REACTION window serves players one by one without interleaving initiative from R_abilities. (b) One window at a time; remaining offers wait in `pending_offers`. (c) Effect expiration per `triggers.EXPIRY` (not every "until" text has its own event). (d) Text classification is heuristic — it is a hint, not a source of truth; when implementing a card, verify the window in tirules.

**54.8 Window reachability — a component must reach the player at its moment** (audit 2026-11-12). Sources: `docs/rules_tirules/R_action_phase.md` (each player has a turn in initiative order; "at the start of your turn" resolves on every turn, including the first and a turn in which a player passes), `R_abilities.md` (Timing: an ability resolves at the moment described in its text). Code: `core/turn_flow.py`, `core/triggers.py`, `core/hooks/reactions_misc.py`, `src/audit/timing_reach.py`; tests: `tests/test_timing_reach.py`.
- **The first turn of the action phase has a "start of turn".** `next_phase` (STRATEGY→ACTION) after `PHASE/START` emits `TURN/START` for the first player and opens a `turn_end_window` pause with `ended_player=None` (window for cards in hand "at the start of a/another player's turn" without an "end of turn" window). Previously only `end_turn` emitted `TURN/START`, so the first turn lost those abilities (Infantry II, Transit Diodes, Extreme Duress, Military Support…).
- **The phase does not end over open decisions.** `can_advance_phase` = false, and `next_phase` raises `ValueError` while a timing window (`pending_window`) is active or players have offers (`pending_offers`) — e.g., "at the end of your turn" offers from the last turn of the phase. Phase skip (God-Mode) also clears offers.
- **A mandatory ability that fired automatically is visible.** `triggers.fire` runs a component's hook (`covers`) without asking and — when it changed state — appends `ability_notes` → `ability_used` feed fact + notification (user decision from 62.3 extended to all automations).
- **A reaction card in hand signals itself.** `/action-card/playable` and `/promissory/playable` have a `reaction` field (window other than ACTION); the hand dock polls playability continuously and when a reaction window is open pulses the tab and the "Play now: <card>" button even when the hand is collapsed. Behavior depends only on the VIEWER's hand (43.4: nothing leaks to others).
- **Guard:** `timing_reach.analyse` — every event hook has a `fire` emission, every card/note with an effect has a window provider, every effect with a window has a channel (auto / offer / hand / "Available now" / button / modifier). Report: `OKNA_CZASOWE.md` §2a (list of components without an effect that "slip away" in-game).

**54.9 On-screen visible windows and their closure** (user report 2026-11-15: "timing windows should be visible and it should be clear when leaving them", example Salvage Operations). Sources: `R_abilities.md` (Timing: an ability resolves at the moment described in its text; "after" = immediately after the event), asset texts (`so`: "After you win or lose a space combat ... if you won the combat, you may also produce 1 ship in that system of any ship type that was destroyed during the combat"). Code: `core/timing_view.py`, `core/battle.close_combat`, `GET /window/open-now`; tests: `tests/test_timing_view.py`.
- **Combat does not close over decisions.** `close_combat` raises `ValueError` when offers are pending (`pending_offers`). Previously closing combat deleted `active_combat`, leaving the Salvage Operations offer ("produce 1 ship … destroyed during the combat") dead (destroyed ship types live on combat) — the player lost the ability without warning. Turn, phase, and voting gates already work the same way (54.8).
- **Public window bar.** `timing_view.describe_open_windows` describes in English every window open NOW (`reaction_cards.open_windows`): label ("After a space combat is won"), subject, system, "what closes it" (only where determinable from the provider, otherwise "Ends with the next game step"). UI shows them in the decision center to all players, and a window that just passed briefly as "Closed". A card in hand whose window passed without the player playing it produces a private "Window closed" message (only to the hand owner).
- **Only windows that matter** (user report 2026-11-15: "3 windows at once is too much"). A window enters the bar only if something in the game can still react to it from hand (`timing_view.live_points`): an action card outside the discard pile (deck + ALL hands combined — set derived from the public discard pile, does not say who holds the card) or a promissory note in someone's hand, in both cases with an engine effect. Public abilities (technologies, factions, leaders, relics) do not use the bar — they act automatically or via offer / "Available now". UI: one quiet chip "Windows · N open · M closed", list on click; prominent "Window open now" card only for the card owner.
- **Nothing leaks from hand (43.4).** The bar does not say who holds a card. A window whose very existence depends on hidden info (Acquiescence: opened only when someone holds the note) has `OpenWindow.public = False` and does not enter the bar.
- ⚠ ASSUMPTION: windows still last "until the next committed action" (53.5) — the bar does not extend them or pause the game; the protective pause from 43.4 pt 4 remains a separate stage.

**54.10 Protective pause in key windows — 10 s** (user decision 2026-11-15; implements 43.4 pt 4 in selected windows). Code: `core/reaction_pause.py`, `timing.require_no_reaction_pause`, `api/state_service.replace_state` (`sync`), middleware `_expire_reaction_pause`, router `reaction_pause.py`, UI `ReactionPauseBanner`; tests: `tests/test_reaction_pause.py`.
- **Paused windows:** declared strategic action (Coup d'Etat; blocks first primary pick), revealed agenda (Veto, Diplomatic Pressure, riders…; blocks first vote/abstain), won combat (Salvage; blocks "Close battle"), Sustain Damage used in combat and in Space Cannon Offense (Direct Hit, Reflective Shielding; blocks subsequent combat and Space Cannon steps), end of strategy phase (Naalu Gift of Prescience; blocks "Next phase" — eligible: players with a promissory note in hand excluding the owner of the faction note reacting in this window, `promissory_play.faction_note_owners`; user decision 2026-11-22).
- **Opening:** after each committed game step (outside God-Mode and technical operations), `sync` checks key windows. A pause opens when (1) a card outside the discard pile with an engine effect can react to the window (`timing_view.live_relations`) and (2) at least one player who can be a party to the window per card text ("you" = subject, "another player" = others, no relation = everyone) has ≥1 action card in hand. All such players are prompted — including those without a matching card (43.4: behavior does not depend on hand contents). The same window does not pause twice (`reaction_pause_seen`).
- **End (changed 2026-11-16, see 54.11):** the pause lasts a FIXED duration set by the host (default 4 s, plus optional "More time") per server clock (`POST /reaction-pause/release` from client or automatically on any subsequent POST). Passes do NOT shorten the pause (shortening would reveal that no one has a card). During the pause, cards may be played (that is its purpose); a window that disappeared (Coup ended turn, Veto changed agenda) ends the pause.
- ⚠ ASSUMPTIONS: (a) bots pass automatically upon window opening (54.11; no reaction AI yet); (b) promissory notes in hand count toward "someone can react", but only players with action cards are prompted; (c) remaining windows still last "until the next committed action" (HOLD as rewind).

**54.10a Pausing combat after the last side's Sustain Damage** (user decision 2026-11-17; C_action_cards, F_mentak ambush/4.1). The "after Sustain Damage" window of the side assigning losses LAST (including sole assigner — Ambush hits) previously closed in the same step: Direct Hit / Reflective Shielding had no chance to play. Now `battle.assign_combat_hits` leaves combat in the `ASSIGN` step (`ActiveCombat.sustain_hold`, assignment window closed) if `reaction_pause.would_open` — a protective pause opens; only "when/after Sustain Damage" windows are visible. After the pause, `battle.release_sustain_hold` (from `step_settle`) advances combat (`_after_losses`). Reflective Shielding during the hold opens a new assignment for the opponent (`battle.add_combat_hits`). Ambush hits have a separate pause key (`stage: start`). The hold is BEFORE round resolution (winner/draw), so a Direct Hit from a side with no ships can still change the combat outcome. Tests: `tests/test_reactions_combat.py`, `tests/factions/test_rulings_mentak.py`.

**54.11 Fixed-length reaction windows + engine auto-pass** (user decision 2026-11-16: with 6 players, pauses up to 10 s and clicking "Pass" accumulated in a long game). Applies to protective pause (54.10) and Sabotage window (53.6). Code: `core/reaction_window.py`, `core/reaction_pause.py`, `core/card_hold.py`, router `reaction_settings.py`, UI `ReactionPauseBanner`, `HeldPlayBanner`, `ReactionSettings` (action panel; formerly `ReactionAutoPassToggle`), `SettingsModal` ("Reaction windows"); tests: `tests/test_reaction_window.py`.
- **Fixed window duration.** A window always lasts `GameState.reaction_window_seconds` (set by host: on new game from Settings or during an ongoing game `POST /reaction-settings/window`, range 2–30 s, default 5 s - changed 2026-11-18). It ends EXCLUSIVELY by elapsed time (or playing a card that closes the window: Sabotage, Coup…). Passes shorten nothing. Reason (43.4): window duration is the only signal visible to others; if it ended on all-pass and the engine passed for players without a card, an instant end would reveal that nobody has a card.
- **Engine auto-pass.** The engine knows hands, so when opening a window it automatically passes for every eligible player who (1) has no reaction card in hand playable NOW (`action_cards.playability`: `reaction` and `playable`), (2) enabled "Skip all reactions", or (3) is a bot (no reaction AI yet). Only a player with a matching card sees a decision prompt (expanded hand + "Pass"). Others see the same countdown bar "Waiting for reactions…".
- **Passes are private.** The `passed` list (and who requested time) is visible only to the player themselves: state projection (`visibility`) and web-data redact it to "whether I have passed". The "N/M passed" counter was removed (it would leak how many players hold a card).
- **"More time" (+10 s, once per player per window).** Any eligible player per public info may request it (even one for whom the engine auto-passed), so a request reveals nothing about the hand (bluffing allowed). Others see anonymously "Someone asked for more time"; Activity feed has no name.
- **"Skip all reactions"** (`PlayerPrivateState.auto_pass_reactions`, private; `POST /reaction-settings/auto-pass`). The engine passes for the player in EVERY reaction window, even when they have a card they could play (e.g., Sabotage). Enabling during a window passes immediately. The window lasts the same duration, so the setting is invisible to others. Optimistic STOP/Hold (43.4 pt 1–3) remains available.
- **Time-out release without client.** A Sabotage window whose time has expired resolves on any subsequent POST (middleware, like protective pause), not only from the browser countdown.
- ⚠ ASSUMPTIONS: (a) auto-pass is evaluated once at window opening (hand does not change during the window; enabling "Skip all reactions" passes immediately, disabling does not undo a pass); (b) a reaction card playable in ANOTHER open window also counts as "has a card" (the player is prompted - this reveals nothing since window duration is fixed); (c) "More time" = +10 s, once per player in a given window.

**54.12 Pass declarations, mutes, and quick windows** (user decision 2026-11-18: out-of-turn reactions are rare, and waiting on every window slows down the game). Code: `core/reaction_prefs.py`, `core/reaction_window.py`, `core/reaction_pause.py`, `core/card_hold.py`, `core/triggers.py` (muted offers), router `reaction_settings.py`; UI: "Reactions" panel in the action panel (`TurnControls`); tests: `tests/test_reaction_prefs.py`.
- **Pass declarations (private, `PlayerPrivateState.reaction_prefs`).** A player pre-declares a pass in a window category: `all` (every window), `strategy` (declared strategic action - Coup d'Etat), `agenda` (revealed agenda - riders, Veto…; equivalent to "No whens / No afters"), `combat` (won combat, Sustain Damage - Salvage, Direct Hit…), `sabotage` (action card played by another player). Duration: `turn` (until end of current active player's turn), `round` (until end of round), `agenda` (current agenda only), `combat` (current combat only), `always` (until canceled). An expired declaration is removed after each step (`step_settle`). "Skip all reactions" (54.11) = `all` / `always`.
- **"Ask me only when it concerns me"** (`only_involved`). The engine passes for the player in a window that does not concern them (from PUBLIC info): concerns them when the player is a party to the event (`subject`), is named in the window context / played card parameters, or has units/planets in the context system. A revealed agenda concerns everyone.
- **Muted cards and offers.** A reaction card in hand with a muted NAME (all copies, e.g., Sabotage) does not count as "has a card" (auto-pass as if without a card) and does not pop up in decision prompts. A muted component "you may" offer (`covers` key) is not created - it is a pre-made "no" decision by the player; mandatory decisions are never muted.
- **Mid-window application.** Changing a declaration passes immediately in ongoing windows (like 54.11); canceling does not undo a pass.
- **Quick windows (host setting, `GameState.quick_reaction_windows`, disabled by default).** A window ends immediately when all eligible players have passed (including via engine auto-pass), and if all passed at opening - does not open at all. Speeds up the game at the cost of information: quick closure reveals nobody reacted / had a card (conscious host choice, described in UI).
- **"No whens" / "No afters" (like in AsyncTI4).** Half-agenda declarations `agenda_when` / `agenda_after` (typically for duration `agenda`), buttons in the Council window (`AgendaPassButtons`) right after revealing an agenda. A reaction card (action card or promissory note) matching EXCLUSIVELY windows of the declared moment does not count as "has a card"; both halves together = pass for the whole agenda. The `when` and `after` windows of a revealed agenda are already a single pause (`PAUSE_POINTS`).
- ⚠ ASSUMPTIONS: (a) "turn" = (round, phase, active player) tuple - a `turn` declaration expires when the active player or phase changes; (b) card/offer mute lasts until canceled; (c) faction components with a usage window (Quash, Instinct Training) are not muted individually - category declarations apply to them; (d) on a half-declaration, a faction component with a usage window still counts (the engine does not know its moment) - the player is prompted.

- ⚠️ ASSUMPTION (54.12 e, awaiting user decision): AFK = 2 consecutive reaction windows ended by timeout without the player passing, asking for time, or doing anything in the UI; the engine then auto-passes for them until their next action. "This combat" pass = until the active combat (same system/planet/players/round) ends. Component/agent mutes (combat/turn/round/always) are private and only affect the engine's auto-pass, never the public eligible list. "Bluff jitter" (host, 0-2 s, only with Quick windows) shrinks an all-passed window to 50-100% of that value instead of closing it instantly. Tests: `tests/test_reaction_pacing.py`.
