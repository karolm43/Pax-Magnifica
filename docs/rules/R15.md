## 15. Planet Type: `planetTypes` Field (List) vs `planetType` — ✅ VERIFIED (data)

📎 tirules: [Planets](../../../../rules_tirules/R_planets.md) · [Legendary Planets](../../../../rules_tirules/R_legendary_planets.md)

Source: AsyncTI4 planet data (`assets/planets/*.json`). Some sources (e.g., `thunders_edge`)
provide planet type as a `planetTypes` list (e.g., `["FACTION"]`) and DO NOT have a single
`planetType`. Consequences and fix:
- Backend: `PlanetDef` stores both fields (`planet_type`, `planet_types`).
- Frontend: the planet preview previously read only `planetType` (single) — for `thunders_edge`
  planets, color/label/faction icon were missing. Fix: effective type =
  `planetType ?? planetTypes[0]` in `PlanetDetailsCard` (`effectivePlanetType`,
  `PlanetGlyph`) and in `PlanetCard/planetCardStyle.ts` (`getPlanetIconSrc`).
- Artwork (`cardImage`) and descriptions (`flavourText`) for `thunders_edge` planets do not exist in the data —
  they cannot be generated; the frontend fetches artwork from CDN when a path is available.
